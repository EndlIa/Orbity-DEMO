# 适配流程

1. 打开 `#/adapter`，粘贴或打开一个 `.ts` / `.js` / `.mjs` 模块。仓库的“适配此源码”链接可载入已知示例。
2. 识别并选择同步工厂，填写资产 ID；单位和许可仅在核实后填写。识别规则支持 `export function`、导出的函数变量、`export default`，以及能解析到本地函数的 `export { local as alias }` / `export { local as default }`；工作台会保留导出名并显示规则。
3. 生成并审查入口、实例运行时、原始源码、清单草稿和适配报告；下载 ZIP。
4. 解压后解决模块依赖。TypeScript 需要支持 TS 的构建工具。入口返回 `{ root, tick, dispose }`，tick 使用实例自己的时间。
5. 实际验证工厂、资源所有权、动画、实例隔离、边界与编辑等级，再完善 `orbity.draft.json` 并保存为 `orbity.json`。
6. `npm run orbity -- validate <orbity.json>` 验证 schema 与部分跨字段约束。
7. `npm run orbity -- inspect <bundle-dir>` 检查入口、清单格式并计算字节级内容摘要。输出只表示这些检查通过，不表示完整协议一致性。

当前范围：单文件入口的机械封装，不自动迁移独立应用、补全多文件依赖、推断参数、识别真实尺寸或验证许可证。规则会排除异步函数、生成器、类、模块重导出、导入或无法解析的绑定、可能重新赋值的绑定，以及未满足的必需函数参数；这些原因会写入适配报告。 报告同时给出 `adaptation.mode`（`object-asset-candidate`、`simple-app-candidate` 或 `unsupported`）和带严重程度的适配计划；简单应用目前只提供识别结果，不生成对象资产入口。超出范围的网络、Worker 或动态依赖会标为暂不支持。导出函数列表仍可能包含非模型函数，必须通过运行时确认。静态线索按 AST 标识符收集，可能误报或遗漏；解析过程不执行源码，生成的入口在导入时仍会执行源码，不能视为沙箱或安全证明。

清单使用递归排序的键、UTF-8、2 空格缩进和末尾单个 LF。源码不做换行或字节规范化。摘要采用 spec/README.md 的算法；当前工具拒绝全部符号链接。尚未实现独立 packer 比对、运行沙箱、完整 C1–C8 或发布。

Sony 的预览使用 `src/adapted/sony.ts` 中人工迁移的纹理接口版本，原始源码保留。从 Sony 仓库进入 Adapter Lab 可选择导出已审查的迁移配方；仅匹配该固定版本的原始源码。通用生成器仍只封装入口，不自动迁移任意 Canvas 调用。

工作台提供“完善资产清单”编辑器，使用与 CLI 相同的 JSON Schema 和跨字段规则。校验通过不会把草稿标记为已认证。仓库中可对已人工接入的示例运行双实例检查，下载包含初始边界和资源释放观察的报告。
